# 发布数据与隐私边界

## 默认报告

报告采用`metadata_policy=minimal`：

- 不记录主机名、操作系统账号、UID/GID、个人邮箱、用户目录或工作目录。
- 不记录网络接口、网络地址、MAC地址、硬件型号／ID、物理拓扑、GPU UUID/LUID或序列号。
- 不记录测试开始／结束的日历时间，也不记录详细内核release。
- 不记录操作系统、驱动版本、物理内存容量或环境清单。
- 仅保留后端类别、必要的算术能力、测试参数、相对耗时、应用数据占用和校验结果。

源码仓库不发布真实运行JSON、实际设备／环境清单或部署信息。既有测量记录保存在本地忽略目录，不改写其中的性能数据。
测试时长使用单调时钟，不需要导出日历时间。

## 文档示例

账号在运行时动态获取，不提供连接流程或部署示例。
仓库自己的公开GitHub地址、GitHub noreply身份和标准系统路径可以保留。
构建默认不带调试符号，并通过`-ffile-prefix-map`将构建根路径映射为相对路径。

## 发布前检查

```sh
make privacy-check
make privacy-history
```

前者检查Git跟踪文件及非忽略的新文件；后者还检查所有本地可达Git提交的文件内容、作者／提交者身份和提交消息。
诊断只显示文件位置与问题类别，不打印命中的隐私或凭据值。
公开源码集合中不接受运行报告JSON；这些文件即使已精简元数据，也应保存在忽略目录。

对不在发布集合内的报告或日志，可单独检查：

```sh
python3 tools/check_privacy.py --files results/run.json
```

检查覆盖：

- 本地用户目录、个人邮箱、本地域名、字面量运行账号。
- 私有／本地网络地址、MAC地址及不合规的报告身份字段。
- 私钥、访问令牌、云密钥、明文凭据赋值、带凭据的URL和误加入的环境／密钥文件。
- 自动导出主机名／物理拓扑的C API调用，以及报告中的环境身份与日历时间。
- Markdown中的部署角色、连接命令和实际硬件编号。

个人邮箱默认按需审查；GitHub noreply和保留示例域允许用于公开提交／示例。
检查还会识别当前审查进程的非通用本地账号，帮助阻止把实际执行记录直接放进文档。

## 日志和本地文件

`build/`、`results/`、日志和常见凭据文件默认被Git忽略。
忽略规则不会删除本地文件；历史原始报告或调试产物仍可能含有仅供本地使用的信息。
驱动失败诊断、用户提供的字符串及自定义编译选项仍应在发布前检查，不能把默认精简元数据理解为任意日志都可公开。

## 已发布历史

删除当前文件中的敏感内容，不会自动清除旧提交。历史清理需要单独授权，并需使用带预期旧SHA的`--force-with-lease`防止覆盖并发更新。
清理提交使用公开仓库账号的noreply身份，不使用自动推导的本地邮箱。旧本地引用与reflog可在确认后清除。

Git历史替换只能更新当前受控引用；平台缓存、旧链接和其他人的克隆可能仍持有旧对象，需要平台支持或副本持有者另行处理。
任何模式检查都有边界，本项目结合内容审查、回归测试与Git历史检查报告实际审查范围，不承诺对第三方副本作无法验证的删除保证。
